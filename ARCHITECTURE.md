# М&T: устройство и корректность

## Границы модулей

`domain/markov.dart` задаёт программу и правила. `domain/parser.dart` разбирает только исходный текст и Σ. `execution/markov_interpreter.dart` непосредственно реализует определение НАМ. `compiler/markov_compiler.dart` преобразует разобранную программу в конечную таблицу δ через `TuringMachineBuilder`. `execution/turing_simulator.dart` исполняет только таблицу переходов. `WordTapeCodec` отдельно кодирует вход и декодирует остановившуюся ленту. `execution/verification.dart` сравнивает две независимые реализации. `storage` сохраняет JSON, `ui` управляет визуализацией и запуском.

Компилятор не принимает входного слова. Одна машина повторно используется для любых слов над Σ. Генерация не вызывает интерпретатор, не анализирует результат вычисления и не использует нейросеть.

## Алфавиты и семантика строк

Σ — непустой входной алфавит. Рабочий пользовательский алфавит A содержит Σ и все символы обеих частей правил. Благодаря этому правила могут вводить счётчики, цифры и вспомогательные буквы, отсутствующие во входе.

Символ — Unicode scalar value (`String.runes`), а не UTF-16 code unit. Визуально составной emoji или буква с комбинируемым знаком может состоять из нескольких символов; нормализация Unicode намеренно не производится. Пустое слово — пустая строка; ε в интерфейсе является обозначением. Буквально введённая ε, если включить её в Σ, считается обычным символом.

Пробелы вокруг оператора игнорируются, внутри частей правил не поддерживаются. Поддерживаются отдельные строки комментариев `//`; inline-комментариев нет. `->` и `->.` являются синтаксисом, `.` и `< >` запрещены в частях правил. Ограничения явно проверяет парсер. Пустая программа корректна и сразу останавливается.

## Формальная машина

Используется детерминированная одноленточная машина

M = (Q, Σ, Γ, δ, q_start, F),

где F содержит две успешные остановки: нет применимого правила и выполнено заключительное правило. Это эквивалентно модели с одним q_halt, но сохраняет причину завершения. В состояниях F нет исходящих переходов. Неопределённый переход вне F является ошибкой исполнения, а не успешной остановкой.

δ(q,a) = (q',b,D), D ∈ {L,R,S}. Все переносы, поиск и возвраты разложены на такие переходы. Поле `phase` у состояния — только пояснение для интерфейса, симулятор его не исполняет.

## Представление ленты

В начале макрошага лента имеет вид `σ w λλ…`, все остальные ячейки пусты. Маркер начала находится в ячейке 0, головка при запуске — в ячейке 0 на σ, даже если слово пусто. Начальный переход переводит её в ячейку 1; универсальный макрошаг начинается там. Позиции ленты — произвольные целые числа; `SparseTape` не ограничивает их знаком или фиксированной длиной.

Внутренние ID символов:

- blank (λ) = −1;
- маркер начала σ = −2;
- отмеченный символ x имеет ID `−x−10`, в том числе отмеченный σ имеет ID −8.

Пользовательские Unicode ID неотрицательны. Поэтому пользовательские `#`, `$`, `□`, `⊢`, `⊣` никогда не конфликтуют с техническими символами, хотя отображение иногда совпадает. Экспорт сохраняет именно численные ID.

Технический Γ состоит из A, пустого символа, маркера начала и отмеченных вариантов элементов A∪{σ}. Метка опоры хранит исходное значение символа.

## Выбор правила и поиск самого левого вхождения

Для каждого правила создаётся отдельный автомат поиска. Состояние k означает, что суффикс уже просмотренной части слова совпадает с префиксом образца длины k. Это префиксный автомат Кнута–Морриса–Пратта; префиксная функция и таблица переходов вычисляются при компиляции.

Сканирование идёт слева направо. Первое полное совпадение фиксированного образца имеет минимальную начальную позицию. Перекрывающиеся вхождения не пропускаются благодаря префиксным возвратам.

Если прочитана первая λ за словом без полного совпадения, машина возвращается к σ и начинает проверять СЛЕДУЮЩЕЕ правило с начала слова. Она никогда не выбирает более раннее в слове вхождение менее приоритетного правила, пока не доказана неприменимость текущего. Если следующего правила нет, машина останавливается в состоянии «нет применимых правил».

Пустой образец совпадает сразу в начале слова. Поиск для него не нужен, но переход к опоре всё равно выполняет δ.

## Опора и замена

При равной длине машина записывает последний символ замены в переходе, которым найдено совпадение. Остальные ячейки найденного вхождения она перезаписывает справа налево. Хвост ленты остаётся на месте, опора не нужна.

При разной длине машина возвращается к ячейке перед совпадением. Она перезаписывает первые `min(|u|, |v|)` ячеек символами замены и отмечает последнюю из них как опору. Если одна из частей пуста, опорой становится ячейка перед совпадением, в том числе σ при вставке в начало слова.

Справа от опоры машина выполняет только операции, необходимые для изменения длины. Она удаляет `|u| − |v|` символов при сокращении или вставляет оставшиеся символы замены в обратном порядке при росте. Затем снимает отметку и возвращается через σ к первому символу слова.

## Удаление: сдвиг влево

Удаляемый символ стирается, головка идёт к следующей ячейке. Прочитанный символ s хранится в конечном управлении: для каждого s существует своё состояние. Источник стирается, головка идёт влево и записывает s в свободную ячейку, затем проходит к следующему источнику.

Так свободная позиция перемещается вправо, а хвост — на одну ячейку влево. Когда прочитана первая пустая ячейка λ, она переносится в последнюю освобождённую позицию. Хвост после слова остаётся пустым; правый ограничитель не используется. Машина идёт влево до единственной отмеченной опоры. Ни один неотмеченный символ хвоста не теряется: каждый сначала прочитан и сохранён состоянием, а затем записан в соседнюю ячейку.

## Вставка: сдвиг вправо

Начальное состояние несёт вставляемый символ c. На каждой ячейке машина читает s, записывает переносимый символ и идёт вправо в состояние «несу s». При чтении λ записывает последний переносимый символ в эту пустую ячейку и возвращается к опоре. Следующая ячейка и так пуста; правой границы не создаётся.

Переносимый символ хранится в имени конечного состояния. На ленте не требуется внешний буфер, а в симуляторе — операция вставки в строку.

## Повтор и остановка

После обычного правила возврат идёт к автомату ПЕРВОГО правила. После заключительного правила возврат идёт в отдельное состояние F. Если все правила неприменимы, остановка происходит без изменения слова.

На границах макрошагов выполняется инвариант `σ w λλ…`, отметок и внутренних пустот нет. Декодер проверяет σ в ячейке 0, читает слово до первой λ и проверяет отсутствие лишних записанных ячеек. Во время сдвигов промежуточная лента ещё не является выходным словом и не декодируется как готовый результат.

## Аргумент корректности

База: кодировщик создаёт `σ w λλ…` для любого w∈Σ*. На каждом макрошаге автоматы проверяют правила в исходном порядке; первый успешный автомат находит левейшее вхождение. Перезапись и сдвиги сохраняют незатронутый префикс и суффикс и заменяют ровно найденное u на v. Восстановление опоры возвращает инвариант. Следовательно, по индукции последовательность слов на границах макрошагов совпадает с последовательностью слов НАМ.

Если НАМ останавливается заключительным правилом или отсутствием применимого правила, машина достигает соответствующей успешной остановки с тем же словом. Если НАМ выполняет бесконечно много подстановок, машина выполняет бесконечно много конечных макрошагов. Каждая макрооперация конечна на конечном слове. Технические лимиты приложения могут прервать любой из этих процессов и не считаются доказательством остановки или расхождения.

Это описание относится ко всем программам поддерживаемого синтаксиса, успешно скомпилированным в пределах ресурсов. Тестирование конечного множества входов дополняет аргумент, но не заменяет его.

## Стоимость

Пусть n — текущая длина слова, u и v — части применимого правила. Поиск каждого правила требует O(n) переходов после построения префиксного автомата. При замене выполняется по одному сдвигу на каждую добавленную или удалённую ячейку. С учётом перезаписи и возврата к началу это даёт O((1 + d)·(n + |v|)) переходов, где d — разница длин по модулю.

Число состояний, отвечающих за сдвиги, порядка O(d·|A|); переходов — O(d·|A|²). Действуют пределы 40 000 состояний и 500 000 переходов; при превышении компиляция завершается с понятной ошибкой, таблица не обрезается.

## Исполнение, отзывчивость и отмена

Компиляция выполняется через `compute` в isolate с debounce 400 мс. Номер редакции исключает публикацию устаревших результатов. Изменение только входного слова повторно использует машину. Уже запущенная устаревшая компиляция вычисляется до своего лимита; её результат отбрасывается.

Проверка набора выполняется отдельным isolate с прогрессом; отмена уничтожает его немедленно. Ограничения: длина набора ≤8, всего ≤10 000 слов. В версии 1.1 основной экран показывает только исходник и листинг δ. Проверка на слове открывается отдельно и выполняется в isolate; лента и пошаговое управление убраны из интерфейса. Время работы считается без пауз. История — ограниченная очередь, таблицы и списки — виртуализированные.

Лимит длины слова относится к интерпретатору Маркова, лимит занятых ячеек — к симулятору Тьюринга. Это разные технические пределы: если один процесс прерван, модуль сравнения не объявляет эквивалентность.

## Хранение и экспорт

Два чередующихся снимка `workspace_a.json`, `workspace_b.json` хранят проекты, выбранный ID и номер поколения. Каждый новый снимок сначала пишется во временный файл с flush; при сбое остаётся второе поколение. Загрузчик выбирает самый новый полностью валидный снимок. Записи сериализованы. Импорт проверяет формат, размер и поля и создаёт новый ID, не перезаписывая другой проект.

JSON машины содержит все состояния, переходы и численные символы, начальное состояние и множество остановок. Сам по себе он является полным результатом компиляции. В тесте таблица сериализуется и восстанавливается без исходных правил, затем самостоятельно выполняется общим симулятором.

## Представление версии 1.1

MachineListing показывает только реальные δ из скомпилированной машины. Копирование передаёт все переходы без обрезания, старт, остановки и описание кодирования входа. Символы пользователя заключены в кавычки, поэтому не смешиваются с техническими знаками. Проверка исполнения необязательна и не требуется для появления результата преобразования.

## Интерфейс версии 1.3

Добавлены два независимых способа исполнения каждой модели: выполнение до остановки/лимита в isolate и пошаговое продвижение по исходному объекту симулятора. Для Маркова один шаг равен одной подстановке; для Тьюринга — одному δ. Лента и указатель головки показывают реальные ячейки SparseTape. Выделенная строка определяется исключительно парой (state, read). История ограничена и не подменяет текущую ленту. Сброс, смена ввода и исходника изменяют поколение запуска, поэтому устаревший фоновый результат игнорируется.

Парсер принимает Unicode-стрелки → и →. как обозначения -> и ->.; номера строк сохраняются. Подстановка символа из панели производится в текущем выделении редактора. Табличное представление не меняет JSON-таблицу и направление — лишь отображает внутренний Direction.stay.

## Лента версии 1.4

В исполняемой машине удалён символ правой границы (ID −3). Кодировщик создаёт только σ в ячейке 0 и входное слово справа от неё, остальная лента пуста. Пустые ячейки имеют технический ID −1 и отображаются λ. Для поиска и сдвига конец текущего непрерывного слова определяется первой пустой ячейкой. Компилятор генерирует переходы на λ вместо отдельного конца; это изменение самой машины, а не скрытие символа при отрисовке. Модель сохраняет инвариант: σ, затем непрерывное слово, затем только λ. Экспорт JSON обновлён до версии 2 и не имеет поля правого ограничителя. Симулятор по-прежнему исполняет только обычные δ.


## Версия 1.5: выбор стратегии и оптимизация

`compile` сначала проверяет строго один обычный односимвольный переход a → b при a ≠ b. Такая машина делает единственный проход: начальная команда σ/R, по одной команде для каждого символа рабочего алфавита и λ/STOP. Каждая замена уменьшает число a, не создавая новых a, поэтому однопроходная замена даёт то же итоговое слово и всегда завершается. Для остальных программ используется `compileUniversal`: поиск Кнута–Морриса–Пратта, перезапись совпадения, сдвиги при изменении длины и повторный запуск приоритетов. Исполнитель не выбирает стратегии и не обращается к правилам Маркова.

Оба пути передают настоящую таблицу в `MachineOptimizer`: достижимость, устойчивое уточнение классов по (чтение, запись, движение, класс назначения), объединение только доказанно эквивалентных состояний и детерминированная BFS-перенумерация. Отсутствующие команды и причины остановки учитываются. Бюджет 64 итерации: при отсутствии сходимости объединений нет, остаётся только удаление недостижимых и перенумерация. Цепочки движений головки не сокращаются. Это безопасная оптимизация, а не глобальная минимизация произвольной машины.

Рабочие состояния идут подряд S₁, S₂, …, отдельно STOP (или STOP1/STOP2 для разных причин). Головка начинает на σ. JSON версии 3 содержит канонические названия, внутренние ID, initialHead=0 и только используемые служебные символы. — означает stay, STOP — конечное состояние. Таблица, экспорт, пошаговый и фоновый исполнители используют один объект TuringMachine. Парсер принимает отдельную λ как пустую часть правила; λ и σ не входят в пользовательский алфавит.
