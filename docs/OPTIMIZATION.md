# М&T 1.5 — компактная настоящая машина

Для `1 -> 0`, входного алфавита `01` и любого входного слова компилятор создаёт два рабочих состояния, одно STOP и ровно четыре команды:

| Состояние | Читает | Пишет | Ход | Далее |
|---|---|---|---|---|
| S₁ | σ | σ | R | S₂ |
| S₂ | 1 | 0 | R | S₂ |
| S₂ | 0 | 0 | R | S₂ |
| S₂ | λ | λ | — | STOP |

На входе головка на σ. Для `1111` получаем `0000` за 6 переходов (σ + четыре цифры + λ), для `101010` — `000000` за 8. Слово `000` остаётся прежним за 5 переходов; пустое слово завершается за 2. Таблица от входного слова не зависит. Строки таблицы могут быть отсортированы иначе, их смысл не меняется.

Это результат компиляции, а не сокращённое отображение. `tool/inspect_optimized.dart` печатает таблицу, передаёт тот же объект в `TuringMachineSimulator`, проверяет идентичность каждого исполненного перехода и сохраняет JSON. Реальный вывод — `optimized-execution.txt`, независимый экспорт — `optimized-machine.json`. UI, копирование, JSON, пошаговое и автоматическое выполнение используют этот же объект машины.

## Что исправлено

Прежний компилятор даже замену равной длины выполнял через удаление, вставку и сдвиги ленты. Новый путь допускает только строго один нетерминальный переход a → b с различными одиночными символами. Он заменяет все a на b за один проход. Правило не создаёт новых a; каждый шаг Маркова уменьшает их число, поэтому результат совпадает для всех конечных входов. Дополнительные входные/выходные символы сохраняются. На алфавите из k рабочих символов получается k + 2 команды.

После любой генерации действует общий оптимизатор графа. Он удаляет недостижимые состояния, объединяет состояния только при устойчивом совпадении всех чтений, записей, движений и классов назначения, затем перенумеровывает рабочие состояния BFS от S₁. Причины остановки различаются. При превышении бюджета уточнения классов объединения не выполняются; корректность важнее сокращения. Рабочий алфавит экспорта не содержит неиспользуемых технических меток.

STOP отделён от рабочих S₁, S₂, …; — означает отсутствие сдвига. Головка везде начинает на σ; справа от слова только λ. Отдельная λ в части правила означает пустое слово: `b -> λ` равнозначно `b ->`. σ и λ зарезервированы, поэтому не могут случайно стать визуально неотличимыми символами входа.

## Проверка

- `flutter analyze`: без замечаний.
- Полный набор: 68 тестов прошли; отдельный новый UI-тест компактной таблицы и шести реальных переходов также прошёл. Всего 69 тестов.
- Пройдены все 10 обязательных примеров из задания, включая терминальность, повторные подстановки, пустое слово и дополнительные символы.
- Для обобщений `0 -> 1`, `a -> b` и `1 -> 0` с алфавитом `012` независимые исполнители сравниваются на всех словах длины до 5: 791 проверка.
- Для 40 воспроизводимых случайных программ с двумя правилами сравниваются исходная универсальная и оптимизированная машины на 15 словах каждая: 600 запусков. Сверяются статус, число переходов, положение головки и вся разреженная лента.
- Сложный пример `ab -> ba`, `aa -> b`, `b -> λ` сравнивается с независимым Марковым на всех 63 двоичных словах над `ab` длины до 5.
- `1 -> 1` и чередование `1 -> 0; 0 -> 1` не превращаются в завершающийся проход. Достижение лимита возвращает неопределённый результат, а не утверждение о бесконечности.
- Проверяются настоящая сериализация таблицы и её самостоятельное выполнение, интерфейс компьютера/телефона, копирование, сохранение проектов и фоновые запуски.

Конечные прогоны подтверждают проверенные случаи. Общая корректность односимвольного пути опирается на аргумент выше, а объединение состояний — на сохранение каждой операции детерминированного трансдьюсера.

## Что пока не сокращается специальной стратегией

Несколько правил, заключительные подстановки, тождественные замены, многосимвольные образцы, удаления и вставки используют универсальную компиляцию. Для них действует безопасная оптимизация графа, но число состояний по-прежнему может быть большим. Цепочки перемещений не склеиваются: это может изменить положение головки и смысл последующего чтения. Глобальная минимальность произвольной машины не обещается.

Нативные Windows/Android/macOS/iOS сборки этой версии здесь не проверены; исходники и Flutter-тесты проверены в Linux.

## Как запустить

Распакуйте в новую папку; откройте PowerShell в папке `MT`, где находится `pubspec.yaml`:

```powershell
flutter pub get
flutter run -d windows
```

Для проверки компактного случая введите слева `1 -> 0`, алфавит `01`, вход `1111`. Нажмите «Пошагово» справа и «Следующий переход» шесть раз либо «Выполнить сразу».
