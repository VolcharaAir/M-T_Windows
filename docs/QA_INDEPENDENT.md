# М&T 1.5 — независимая проверка архива

Дата проверки: 23.11.2026.

## Что действительно выполнено

Среда проверки не содержит Flutter/Dart SDK. Поэтому `flutter test`/`flutter analyze` непосредственно в этой среде не запускались. Лог `docs/flutter-test.txt` из архива **сообщает** об 69 пройденных тестах, но это предоставленный вместе с исходниками лог, а не результат нового запуска.

Независимый тестировщик на Python выполнил **реальные переходы** из сериализованных JSON-машин, созданных компилятором, и сравнил их с независимо вычисленными ожидаемыми строками.

| Набор | Что проверено | Проверок | Результат |
|---|---|---:|---|
| Оптимизированная машина v3 | Все двоичные слова длины 0–12, запуск исходного JSON `docs/optimized-machine.json` | 8 191 | 8 191 PASS |
| Оптимизированная машина v3 | 45 случайных двоичных строк длины 100, 1 000, 4 000 | 45 | 45 PASS |
| Универсальная старая машина v2 | Все двоичные слова длины 0–8 для **двух правил, реально вшитых в старый экспорт** | 511 | 511 PASS |
| Согласованность двух архивных примеров | `examples/priority.markov` (3 правила) против старого `examples/priority_machine.json` (2 правила) | 511 | 18 расхождений — **устаревший JSON-файл** |

**Итого успешно выполнено 8 747 независимых запусков JSON-машин.** Это не подтверждает автоматически весь код нового компилятора, особенно универсальную генерацию v1.5: её можно проверить запуском Flutter/Dart тестов.

## Компактная замена действительно работает

`docs/optimized-machine.json` содержит начальное `S_1`, рабочее `S_2`, остановку `STOP` и 4 перехода:

```text
S_1 σ -> σ R S_2
S_2 λ -> λ — STOP
S_2 0 -> 0 R S_2
S_2 1 -> 0 R S_2
```

Все проверенные входы дают `word.replaceAll('1', '0')`, количество переходов точно равно `длина_слова + 2`, положение головки при остановке — `длина_слова + 1`.

## Обнаруженная проблема: устаревший пример

Файл `examples/priority.markov` содержит три правила:

```text
00 -> 1
11 ->. 0
01 ->. 1011
```

Но файл `examples/priority_machine.json` имеет `version: 2`, начальное состояние `q2` и состояния только для `rule=1` и `rule=2`; третье правило в нём отсутствует.

На слове `01` исходный Марков даёт `1011`, а экспортированная старая машина — `01` (ничего не меняет). Это **не доказательство ошибки нового компилятора**: архивный файл был сгенерирован до изменения алгоритма-примера и не обновлён. Нужно заново экспортировать его компилятором текущей версии и повторить проверку.

## Подготовленные дополнительные Flutter-тесты

`test/extra_regression_test.dart` добавляет 18 сценарных тестов:

- точное число состояний/переходов односимвольной оптимизации;
- 511 двоичных и 364 трёхсимвольных коротких входов;
- терминальность, многосимвольные подстановки, перестановки, приоритет, пустые стороны, Unicode;
- независимое сравнение Маркова и Тьюринга на всех двоичных входах длины 0–6 для трёх правил;
- незавершающиеся правила и защита зарезервированных `σ`, `λ`.

Это подготовленные тесты; **здесь не запускались** за отсутствием Flutter/Dart SDK.

### Проверить у себя (PowerShell, каталог с `pubspec.yaml`)

```powershell
flutter pub get
flutter test test/extra_regression_test.dart
flutter test
flutter analyze
python tool/independent_export_check.py
```

При наличии Python последняя команда проверяет реальные JSON-экспорты; предупреждение об устаревшем двухправильном файле будет ожидаемым, пока этот пример не регенерирован.

## Что пока не подтверждено

- Запуск собранного EXE и APK на физических устройствах.
- Сборки для macOS/iOS.
- Реальное выполнение кода Dart нового универсального компилятора в этой тестовой среде.
- Корректность на *всех возможных* нормальных алгоритмах Маркова: конечные тесты математически не доказывают полную эквивалентность.
